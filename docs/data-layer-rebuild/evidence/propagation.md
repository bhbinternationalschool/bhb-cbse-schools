# propagation — Cross-screen and cross-device propagation of a Masters change (S3, S5), end to end

## summary
A Masters edit on origin/main reaches the database correctly and safely (section save → masters_write_slices, all-or-none, slice stamps checked, desk revision bumped), but it reaches other SCREENS only inside the tab that made it, and reaches other TABS and other DEVICES only by accident. The page-memory copy (bhb_masters_v5 in browserStorage.memoryCopies) is per tab; the single notification is a same-window CustomEvent 'bhb-masters-updated' that 8 components listen to; the five remaining 'storage' listeners can never fire because the key no longer touches localStorage; the route-priority hydration runs exactly once per tab (AppShell boot effect returns early once bootReady), and after that only 13 screens ever call ensureMastersHydrated (with a 15 s TTL) while 23 re-hydrate SIS. Nothing on /homework, /attendance, /timetable, /students or Staff→Allocate teaching re-reads Masters, so a teacher's phone and any second office tab hold the morning's Masters until a full reload — that is S3 and S5 on the web. Two concrete write-side hazards survive: (1) loadSis() re-aligns every student against the LOCAL masters copy on every read and re-points a student whose section the stale copy does not know to the class's first section, writes that back into the SIS memory copy, and the next whole-roster saveSis carries it with a matching row version — sis_push_guarded then writes it, reverting a section move made elsewhere; (2) a function-only Masters holder (teachingOnly bundle, no slice stamps, no desk revision) pushes the whole classSubjects slice from its snapshot and authorizeFeatureChange drops own-class links absent from the push, so a link the office added since the phone loaded can be deleted silently (within the #524 shrink limits). On the mobile API, loadServerMasters ignores readFailed and caches an empty bundle for 30 s per instance, and on throw returns demo masters — classes and subjects vanish from the app for that window. Homework posts themselves carry only ids and no masters base, so the homework save cannot corrupt Masters; the harm there is the picker (masters.subjects ∩ my.teaching) hiding new subjects.

## findings

### 1. [root] Masters changes never leave the tab: memory-only copy + same-window event, 'storage' listeners dead, hydration schedule runs once per tab  (read-in-code; S3,S5)
Since 10 Oct bhb_masters_v5 lives in a module-level Map inside each page (browserStorage.ts memoryCopies); writeCacheOrInvalidate never touches localStorage for it. The only change signal is window.dispatchEvent('bhb-masters-updated') fired by saveMasters/hydrate/staff-hydrate/CoreDataGate — a same-window CustomEvent with 8 component listeners. The five components that listen to the native 'storage' event (the historical cross-tab channel) can never fire for Masters because localStorage never changes; there is no BroadcastChannel. The AppShell boot effect calls startDeskHydrationBackground(pathname) once and returns early on every later pathname change (`if (bootReady) return`), so client-side navigation never re-runs the CORE tier; after boot a tab re-reads Masters only when one of 13 screens calls ensureMastersHydrated and the 15 s TTL has lapsed, or on full reload. visibilitychange only flushes pending pushes, never re-reads. Net: a second office tab (Timetable/Homework/Students/Staff) and every teacher phone show the Masters of their last page load.
- `apps/web/src/lib/browserStorage.ts:65-66, 136-141, 254-267, 293-299` — bhb_masters_v prefix is MEMORY_ONLY; readCache/writeCacheOrInvalidate use the per-page memoryCopies Map; nothing is written to localStorage
- `apps/web/src/lib/masters.ts:2147-2156, 2178` — persistMastersClient writes the memory copy then dispatches 'bhb-masters-updated' (same window only)
- `apps/web/src/components/shell/AppShell.tsx:205-216, 219-220, 243-258, 269` — visibilitychange only flushes saves; boot effect depends on pathname but returns when bootReady, so startDeskHydrationBackground runs once per tab
- `apps/web/src/lib/deskHydrationSchedule.ts:40-45, 48-80, 361-368` — CORE = rbac, masters, moduleRegistry, sis; no ROUTE_IDS for homework/timetable; startDeskHydrationBackground idempotent per tab
- `apps/web/src/lib/deskHydrateGuard.ts:7, 23-27, 41-55` — 15 s TTL; markDeskHydrated fires 'bhb-desk-first-hydrated' once per desk per page
- `apps/web/src/components/shell/CommsRunningStrip.tsx:92` — one of 5 'storage' listeners (also SchoolHomeDashboard.tsx:74, SessionSelector.tsx:23, AdmissionsWorkspace.tsx:378, AdmissionCrmChatInbox.tsx:95) that cannot fire for memory-only keys

### 2. [root] loadSis() re-points students against the LOCAL masters copy and writes it back; a later whole-roster saveSis carries the reverted section with a matching row version  (read-in-code; S2,S3,S5)
loadSis() runs on every read and calls alignSisToMasters(next, loadMasters()). A student whose sectionId is not in THIS browser's masters copy but whose classId is, is silently moved to the first section of that class (changed=true) and the result is written into the SIS memory copy. 23 screens re-hydrate SIS (fresh rows, fresh versions) but only 13 re-hydrate Masters, so after the office creates section 'Alpha' and moves 5 students, a second tab/device that refreshes the roster (Fee Take, Students, Admissions, student cards) against its stale masters shows the 5 students back in 'A'. saveSis pushes the WHOLE roster (state.students) through sis_push_guarded, which skips only byte-identical rows and writes a changed row whose version matches — these 5 rows match (they were just read) but differ (sectionId) → the move is reverted in sis_students.
- `apps/web/src/lib/sis.ts:1578-1579, 1629-1637` — loadSis: masters = ensureStudentClassLinks(loadMasters()); alignSisToMasters on every read; writeCacheOrInvalidate when slim differs
- `apps/web/src/lib/sis.ts:1452-1529` — alignSisToMasters: lines 1489-1494 'Class valid → first section' re-points sectionId and sets changed=true; 1520-1525 keep rows only when ALL are orphaned
- `apps/web/src/lib/sisNormalizedClient.ts:16-19, 205-226` — pushSisDeskApi sends households/students/tags/classUpgrades of the whole state
- `supabase/migrations/adhoc-export/20260810104449_sis_push_guarded_restore_noop_skip.sql:54-68, 113-120` — no-op skip only when (existing - updated_at) = (incoming - updated_at); otherwise version checked and row written
- `apps/web/src/components/fees/FeeTakeWorkspace.tsx:(grep)` — 16 screens call ensureSisHydrated without ensureMastersHydrated: FeeTakeWorkspace, StudentsWorkspace, AdmissionsWorkspace, ModuleDashboardHost, Student* cards, WaStudentPicker, AdmitCardsPanel
- FIX HINT: alignSisToMasters must never rewrite a row from a copy of Masters that is older than the roster it is aligning (compare masters desk revision vs sis read time, or only align when the desk was loaded in this hydrate); never write alignment results into the copy that saveSis pushes; make saveSis send only rows the UI changed.

### 3. [major] Function-only Masters holders push the whole classSubjects slice from a snapshot with no stamps; own-class links absent from the push are deleted  (read-in-code; S3,S5)
A teacher without the masters module grant is served the teachingOnly bundle (GET 403 → teachingMastersResponse) which has no sliceStamps, so captureSliceBases is skipped (sliceBase=null) and writeMeta never runs. Any saveMasters from that browser therefore sends the WHOLE book with baseUpdatedAt=null; the route takes the featureGate path, skips the revision guard and the slice-stamp check, and merges through authorizeFeatureChange, where for class-scoped features own-class rows 'take the pushed version (or go, if the push removed them)'. masters.class_subjects is classScoped, CRUD, no unionRows. So a link the office added to the teacher's own class after the phone loaded is removed if the role allows delete, and guardSubjectsOverwrite passes (≤10 links and ≤25%). The reachable writer on main is SubjectRulesPanel (periods/week) → saveMasters(next) with the Timetable page's mount-time masters.
- `apps/web/src/app/api/school-data/masters-desk/route.ts:108-118, 78-106, 263-270, 280, 327-370, 396-408` — teachingOnly on 403; revision guard skipped when featureGate; function-only merge; subjects taken from stored; guardSubjectsOverwrite after merge
- `apps/web/src/lib/mastersNormalizedClient.ts:207-221, 240-266, 416-423` — sliceBase null for teachingOnly → whole-book POST with baseUpdatedAt from readMeta() (never written for teachingOnly)
- `apps/web/src/lib/deskFeatureAuth.ts:142-173, 200-206` — own-class rows: pushed version or dropped; delete permission checked per row
- `apps/web/src/lib/rbacFeatureCatalog/masters.ts:5-14` — masters.class_subjects: CRUD, classScoped, slices ['classSubjects'], no unionRows
- `apps/web/src/lib/mastersWriteGuard.ts:106-119` — shrink guard allows up to 10 link removals (and ≤25%)
- `apps/web/src/components/timetable/TimetableRulesSetup.tsx:413-425` — SubjectRulesPanel rewrites the whole classSubjects slice and calls saveMasters(next)
- `apps/web/src/components/timetable/TimetableWorkspace.tsx:136-145, 863` — masters prop is the copy read at mount; no masters listener, no ensureMastersHydrated
- FIX HINT: Serve sliceStamps with the teaching bundle and require them on function-only pushes; in authorizeFeatureChange treat absence as 'unchanged' for classSubjects (unionRows) and accept deletes only by name.

### 4. [major] Mobile API: a failed Masters read is cached as 'no classes' for 30 s per instance; a thrown read answers with demo masters  (read-in-code; S5,S6)
loadServerMasters() awaits fetchMastersDeskFromDb(), which on a Supabase error returns {bundle: empty, readFailed: true} without throwing. loadServerMasters ignores readFailed, builds a MastersState with zero classes/sections/subjects, stores it in mastersCache for MASTERS_CACHE_TTL_MS = 30 s, and every /api/v1 request on that Cloud Run instance (principal snapshot, my-classes, homework, attendance) resolves scope against an empty school until the TTL lapses. If the Promise.all throws, the catch returns defaultMasters() — freshly generated demo classes with random ids — for that request. This is a 200, not a 5xx, so it does not show in the 5xx count.
- `apps/web/src/lib/api/v1/auth.ts:189-222` — mastersCache 30 s; readFailed never inspected; catch returns defaultMasters()
- `apps/web/src/lib/mastersNormalized.server.ts:405-421` — fetchMastersDeskFromDb returns empty bundle with readFailed=true on sliceErr/metaErr
- `apps/web/src/lib/api/v1/staffScope.ts:77-121` — staffSectionScope derives a teacher's sections from ctx.masters; empty masters → no sections → restricted teacher sees nothing
- FIX HINT: Treat readFailed as unknown: keep the previous cache entry (or 503), never cache an empty bundle, and never fall back to defaultMasters() on a real tenant.

### 5. [minor] Homework posts carry only ids and no masters base — the homework save cannot damage Masters; the visible harm is the stale picker  (read-in-code; S5)
publishHw builds {classId, sectionId, subjectId, ...} and createHomeworkPost → scheduleHomeworkSync → homework-desk POST; refuseSaveBeforeLoad guards only the homework desk. The picker, however, is masters.subjects (stale page-load copy) intersected with my.teaching (server answer, 60 s client cache, 30 s server masters cache), so a subject added and linked at 8:30 is absent on a phone open since morning: the teacher cannot post for it and sees 'subject vanished' if it was renamed/relinked. HomeworkWorkspace re-reads Masters only in refresh() at mount / after ensureHomeworkHydrated, never via ensureMastersHydrated or the masters event.
- `apps/web/src/components/homework/HomeworkWorkspace.tsx:222-245, 305-322, 440-469` — refresh reads loadMasters(); subjectOptions = masters.subjects ∩ my.teaching; payload ids only
- `apps/web/src/lib/homeworkPersistence.ts:44-55` — scheduleHomeworkSync: refuseSaveBeforeLoad('homework') then homework desk push; no masters payload
- `apps/web/src/components/staff/useMyTeaching.ts:22-40` — my-classes cached 60 s client-side
- FIX HINT: Homework picker should take subjects from the server's my-classes answer (it already names subject ids) and resolve labels from a Masters copy refreshed on focus.

### 6. [minor] Section rename is Masters-only and propagates by id everywhere; only Exam seating copies class names  (read-in-code; S3)
SIS, attendance registers, timetable, homework, exams, student leave, PTM store sectionId/classId only; the fee desk resolves names from the current masters copy at read time; transport holds no sectionId. So renaming 'A' → 'Alpha' needs no cascade and shows correctly wherever the masters copy is fresh, and shows 'A' wherever it is stale (finding 1). removeSection cascades only staff links; checkSectionRemoval counts masters.students (a local projection), not sis_students. Exam seating plans embed className strings and go stale after a class rename.

### 8. [minor] Every masters-desk GET is a full 235 KB pull: the probe/ETag cache is opt-in and not enabled  (read-in-code; S4)

- FIX HINT: Wrap the slices read path in cachedDeskJson too (tables: masters_desk_slices, masters_desk_sync_meta) and send If-None-Match from hydrateMastersDeskFromDb.
